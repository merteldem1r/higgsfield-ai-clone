I added the prompt improver: a server route, a small database migration and a wand button in the composer. The build passes. I haven't called the route or clicked the button yet, because the migration isn't applied: until you run it, every improve request returns a 500.

## 1. Model and cost
- **Endpoint:** `openrouter/router` on fal. It bills per token at OpenRouter's prices. Fal's older `fal-ai/any-llm` endpoint is marked deprecated, so I didn't use it.
- **Model:** `meta-llama/llama-3.1-8b-instruct`. It's open-weight, doesn't spend time on a reasoning pass (so it answers fast) and costs $0.05 per million tokens in and $0.08 per million out.
- **Per call:** about 300 tokens in and 150 out, so roughly **$0.00003**. That's about 200x cheaper than one Flux Schnell image ($0.006).
- **Cheaper option:** `mistralai/mistral-nemo` ($0.019 in / $0.03 out per million).
- **Better-quality option:** `meta-llama/llama-3.3-70b-instruct` costs about $0.0001 per call, still around 60x cheaper than an image. Switching is a one-line change to `IMPROVER_MODEL` in `src/lib/fal.ts`.
- The prices come from OpenRouter's public price list. I didn't make a paid test call to confirm what fal actually bills.

## 2–3. Route and rate limit
- **`POST /api/improve-prompt`** checks the session the same way `/api/generate` does, then applies the per-IP limit, then calls fal from the server. Input is capped at 500 characters, the call times out after 15s, and the output is trimmed to 500 characters. No credits are charged.
- **Errors it returns:** `UNAUTHENTICATED` (401), `INVALID_INPUT` (400), `IP_LIMIT` (429), `TIMEOUT` (504) and `PROVIDER_ERROR` (502).
- **It needs a new table.** It can't reuse `generations`: `start_generation` counts that table's `ip_hash` rows for the image cap, so improvements would use up people's daily image allowance. The migration `supabase/migrations/20260923200000_prompt_improvements.sql` adds:
  - a `prompt_improvements` table (user id, IP hash, timestamp) with row-level security on and no policies, so only the service role can touch it;
  - a function `start_prompt_improvement` that counts and records each attempt in one locked step, so parallel requests can't slip past the limit of 20. Only the service role can run it.
- Failed attempts still count toward the 20, since fal may bill them anyway.

## 4–5. UI and states
- **Wand button** next to the +, with a small tilt on hover.
  - **Empty input or a generation in flight:** the button is disabled, and hovering it explains why.
  - **Loading:** a brand-coloured ring spins around the button, the prompt text dims, a coloured shimmer sweeps across it, and the text can't be edited.
  - **Success:** the new prompt types itself in over about 0.3–0.9 seconds. An "✨ Prompt improved | ↺ Undo" pill pops into the settings row and restores the original. It disappears once you edit the text or press Generate.
  - **Failed or timed out:** the existing toast appears and the original prompt is left untouched.
  - **Rate-limited:** the toast appears, and the button stays off for the rest of the visit.
- Generate is disabled while the improver is running.
- With reduced motion turned on, the text swaps instantly and there's no spinning ring or shimmer.
- Toast and label text is translated for EN, TR and RU.
- No new dependencies.

## Decisions for you to check
- **English output:** the instructions tell the model to always write the prompt in English, even when the idea is typed in Turkish or Russian, because Flux follows English prompts best.
- **Guest sessions:** clicking the wand gives a guest an anonymous session, the same way the first Generate does.
- **No global spend cap:** improvements aren't counted against the daily demo budget (the `app_budget` table). At the limit of 20 per IP per day, one network can spend at most about $0.0006 a day.
